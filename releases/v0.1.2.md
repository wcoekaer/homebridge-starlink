The npm package is now **`@wcoekaer/homebridge-starlink`**. This release preserves the working Starlink sensors and dashboard camera from 0.1.1 while preparing public publishing under the maintainer's npm scope.

### Changes

- Use the scoped package name for Homebridge registration and public npm publishing.
- Preserve the original accessory UUIDs and `Starlink` platform alias so existing HomeKit accessories can migrate without being recreated.
- Verify that a real child bridge restores the original unscoped accessory cache under the scoped plugin.
- Update installation instructions and release automation for scoped package archives.

### New installations

Download `wcoekaer-homebridge-starlink-0.1.2.tgz` from this release and install it in your Homebridge environment:

```sh
npm install -g /absolute/path/wcoekaer-homebridge-starlink-0.1.2.tgz
```

Once the staged npm release is approved, the package can also be installed with `npm install -g @wcoekaer/homebridge-starlink` or by searching for its full name in the Homebridge UI.

### Upgrade from 0.1.0 / 0.1.1

Install the scoped package and remove the old package **before restarting Homebridge**:

```sh
npm install -g /absolute/path/wcoekaer-homebridge-starlink-0.1.2.tgz
npm uninstall -g homebridge-starlink
```

Keep your existing `Starlink` platform configuration, child-bridge `_bridge` settings, and accessory cache. If you use a `plugins` allowlist, replace the old package name with `@wcoekaer/homebridge-starlink`. Then restart Homebridge. No HomeKit re-pairing is needed.

The GitHub release archive remains usable independently of npm approval. `SHA256SUMS` contains its checksum.
